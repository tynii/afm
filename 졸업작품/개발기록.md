## 1. 기획 (2026-10-12)

- **문제:** 위시가 쇼핑몰 하트·캡처·메모장에 흩어져 있어서 "어디 저장했더라" 하며 찾게 된다.
- **방향 선택:** 하트 통합 / 담아서 모아보기 / 컬렉션 정리 중 **담아서 모아보기**를 골랐다. 하트 통합은 앱마다 따로 만들어야 해서 너무 크고, 컬렉션은 v1 다음으로 미뤘다.
- **핵심 기능:** 위시 담기 → 카드로 모아보기
- **성공 기준:** 링크 10개 + 제목만 2개를 담으면 12개가 카드로 보이고, 카테고리를 누르면 그 종류만 보인다.

**개발 중 막혔던 것**

- **DB 접속 실패 (0단계):** Supabase 기본 주소(Direct connection)는 IPv6 전용이라 이 PC에서 접속되지 않았다. IPv4로 되는 Transaction pooler 주소(포트 6543)로 바꿔서 해결했다. 이 주소는 Vercel에서도 그대로 쓴다.

| 10-18 | 이미지 주소 칸을 평소엔 숨기고 **[이미지 직접 넣기]** 를 누를 때만 열기 | 칸이 늘 보이면 화면이 복잡하다. 자동 추출이 대부분 채워 주고, 막힌 사이트만 직접 넣으면 된다 |
| 10-18 | 링크를 넣으면 이미지뿐 아니라 **제목도** 자동으로 채움. 직접 쓴 제목은 덮어쓰지 않음 | 입력을 줄이려고 |
| 10-18 | 상세·수정·삭제를 "배포 후에" → **배포 전(4.5단계)** 으로 앞당김 | 카드를 누르면 바로 링크로 가는 것보다 제목·링크·메모를 보는 상세 화면이 필요했고, 링크 없는 카드도 눌러서 볼 수 있어야 했다 |

| 10-19 | 오늘의집 상품 페이지 자동 추출 실패 → 성공 | 서버가 보내는 `Accept` 헤더가 브라우저와 달라서 404가 났다. 브라우저 기본값으로 맞췄다 |
| 10-19 | 네이버 플레이스 제목 끝의 ` : 네이버`와 보이지 않는 제어문자 제거 | 제목에 군더더기가 붙어서 |
| 10-19 | 성공 기준 문구에서 "폰에서", "(쇼핑몰, OTT, 전시, 카페)"를 뺌 | 폰 테스트는 다음 단계로 미뤘고, 사이트 예시보다 "서로 다른 사이트"가 핵심이라서 |
| 10-19 | 성공 기준용 위시 12개(링크 10개, 제목만 2개) 담기 | 링크 10개는 모두 다른 사이트(29CM·쿠팡·무신사·오늘의집·티빙·넷플릭스·예스24·NOL 티켓·네이버 플레이스·만개의레시피) |

### 점검에서 찾아 고친 것 (10-19)

| 무엇을 | 왜 |
|---|---|
| 앱 안의 [뒤로]를 브라우저 뒤로가기와 똑같이 동작하게 함 | 새 화면을 쌓는 방식이라 폰의 뒤로가기 제스처와 꼬였다 |
| 상세에 다녀와도 목록의 필터·스크롤 위치 유지 | `상품` 필터를 걸고 위시를 봤다 오면 `전체`로 풀리고 맨 위로 올라갔다 |
| 오류 문구가 입력을 고치면 바로 사라지게 함 | 카테고리를 고른 뒤에도 "카테고리를 선택해 주세요."가 남아 있었다 |
| 폼의 카테고리 버튼을 3칸×2줄 그리드로 | `기타` 하나만 다음 줄로 떨어졌다 |
| 상세 이미지를 잘리지 않게 전체 표시 | 세로 포스터·가로 썸네일이 정사각형으로 잘렸다 |
| 필터 칩 오른쪽 끝을 흐리게 | 옆으로 더 있다는 표시가 없었다 |

## 4. 배포 (2026-10-19)

- Vercel CLI로 `졸업작품` 폴더에서 바로 배포했다 → https://wish-board-brown.vercel.app
- `DATABASE_URL`은 Vercel 환경변수에만 등록했고, `.env`·`.env.local`은 GitHub와 Vercel 업로드에서 모두 뺐다.
- **집 PC와 배포 서버의 차이:** 오늘의집은 집 PC에서는 자동 추출이 되지만 Vercel 서버에서는 403으로 막힌다. 막힌 사이트는 안내 문구가 뜨고 직접 입력으로 저장한다.
- GitHub push만으로는 자동 배포되지 않는다. 코드를 바꾸면 `vercel --prod`를 다시 실행한다.

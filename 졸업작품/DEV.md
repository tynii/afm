# DEV — 위시 모아보기 v1 개발 계획

> 기준: [MISSION.md](MISSION.md) · 핵심 기능 = **위시 담기 → 카드로 모아보기** · 성공 기준 = 링크 10개 + 제목만 2개, 12개가 카드로 보이고 카테고리 필터가 동작

## 1. 화면 (4개, `index.html` 하나에 해시 라우팅)

| 화면 | 역할 |
|---|---|
| 목록 `#/` | 위: 카테고리 버튼(전체·문화·콘텐츠·장소·음식·상품·기타) / 아래: 위시 카드(이미지·제목, 누르면 상세) / `+` 버튼 → 담기 |
| 담기 `#/add` | 제목 → 링크(붙여넣으면 제목·이미지 자동 채움, 수정 가능) → 이미지 미리보기 + [이미지 직접 넣기](누를 때만 주소 칸이 열림) → 카테고리 1개 탭 → 메모(선택) → [저장] |
| 상세 `#/wish/:id` | 이미지 · 카테고리 · 제목 · [링크 열기] · 메모 / [수정] [삭제](확인 창) |
| 수정 `#/wish/:id/edit` | 담기와 같은 입력 폼, 기존 값이 채워진 상태 |

## 2. 데이터 (Supabase 테이블 1개)

`wishes`: `id` · `title`(필수) · `url`(선택) · `image_url`(선택) · `category`(6개 중 하나, 텍스트) · `memo`(선택, 1000자까지) · `created_at`
카테고리는 별도 테이블 없이 텍스트 칸과 고정 버튼 6개로 처리한다.

카테고리별 포함 항목 (앱에는 상위 이름 6개만 보이고, 하위 항목은 고를 때 참고용이다. 분류는 repov 앱 카테고리를 참고했다)

| 카테고리 | 포함 항목 |
|---|---|
| 문화 | 콘서트, 전시, 축제, 연극/뮤지컬, 스포츠 경기, 클래식 공연, 무용/발레, 기타 문화 |
| 콘텐츠 | 영화/텔레비전, 책, 음악, 게임, 강의, 웹툰, 웹소설, 웹 콘텐츠, 기타 콘텐츠 |
| 장소 | 음식점, 카페, 술집, 여행지, 공공 시설, 공원/자연, 놀이공원, 문화 시설, 병원/약국, 부동산, 뷰티샵, 상점, 생활 시설, 숙박 시설, 종교 시설, 주거 시설, 지역, 학교, 헬스장/스포츠 시설, 기타 장소 |
| 음식 | 술, 음식/메뉴, 레시피/요리, 음료, 영양제, 기타 음식 |
| 상품 | 뷰티, 차, 패션, 취미, 문구, 유아동, 전자제품, 가구/인테리어, 리빙, 기타 제품 |
| 기타 | 앱/웹 서비스, 사전적 정의, 일상, 공부, 브랜드, 사람, 운동, 기타 |

## 3. 기술 (6주차 구성 그대로, 새 라이브러리 없음)

`index.html`(React CDN + Tailwind) · `server.js`(Express) · Supabase Postgres(`pg`, `dotenv`) · Vercel 배포

## 4~5. 개발 순서와 단계별 작동 결과

| 단계 | 만들 것 | 끝나면 작동하는 것 / 확인 방법 |
|---|---|---|
| 0 | 폴더 준비, `npm install express pg dotenv`, server.js가 index.html 보여주기 (포트 **3001**) | `npm start` → `localhost:3001`에 빈 화면이 뜬다 |
| 1 | 제목만 담기 + 카드 목록 (`POST`·`GET /api/wishes`, DB 연결) | 2개 담고 새로고침해도 남아 있다 + Supabase Table Editor에서 행이 보인다 |
| 2 | 담을 때 카테고리 선택 + 목록 필터 | 카테고리별로 1개씩 담고 버튼을 누르면 그 종류만 보인다 |
| 3 | 링크·이미지 주소 **직접 입력** | 쿠팡 링크와 이미지 주소를 손으로 넣어 저장 → 이미지 카드가 보이고, 누르면 링크가 열린다 |
| 4 | **자동 추출** `GET /api/preview?url=` (서버가 og:title·og:image를 읽음, 5초 넘으면 중단) | 무신사 링크는 칸이 자동으로 채워진다. 쿠팡 링크는 "직접 입력해줘" 안내가 나오고 3단계 흐름으로 저장된다 |
| 4.5 | 상세 화면 `#/wish/:id` (카드를 누르면 열림): 링크 열기 · 메모 · 수정 `#/wish/:id/edit` · 삭제. `memo` 칸 추가, `GET`·`PUT`·`DELETE /api/wishes/:id` | 링크 없는 카드도 눌러서 상세로 들어간다. 수정·삭제 후 새로고침해도 반영돼 있다 |
| 5 | 폰 화면 다듬기 + Vercel 배포 (**배포 전에 허락 받기**) | 폰에서 성공 기준 12개를 통과한다. 배포 서버에서도 자동 추출이 되는지 다시 확인한다 |
| 6 (선택) | 컬렉션: `collection` 텍스트 칸 + 필터 버튼 한 줄 (디자인은 스케치북·엽서·봉투·파일 포켓 같은 아날로그 모양, DESIGN.md 7절 참고) | 5단계를 통과한 뒤에만 시작한다 |

원칙: 자동 추출은 입력 칸을 미리 채워 주는 보조 기능이다. 4단계가 막혀도 3단계까지만으로 v1 성공 기준을 통과할 수 있다.

## 6. 위험 요소와 대비책

| 위험 | 근거 | 대비책 |
|---|---|---|
| 자동 추출 실패 | 2026-10-12 Node fetch 테스트 결과. 성공: 무신사·29CM·오늘의집·교보·예스24·티빙·네이버 플레이스. 실패: 쿠팡(403)·스마트스토어(로그인 페이지)·넷플릭스·인스타(og 태그 없음) | 직접 입력(3단계)을 먼저 만든다. 실패하면 안내 문구를 띄우고 입력 칸은 그대로 수정할 수 있게 둔다 |
| 배포 서버에서 더 많이 막힘 | 2026-10-19 Vercel(iad1) 측정: 무신사·29CM·티빙·예스24·교보·NOL 티켓·네이버 플레이스·만개의레시피·유튜브 성공, 넷플릭스는 제목만, **오늘의집은 집 PC에서는 되지만 Vercel에서 403**, 쿠팡 403 | 막힌 사이트는 안내 문구가 뜨고 직접 입력으로 저장한다 |
| 제목에 `&amp;` 같은 특수문자가 섞임 | 무신사 og:title 결과 | 서버에서 특수문자를 변환한 뒤 응답한다 |
| 이미지가 깨짐 | 다른 사이트 이미지 직접 표시가 막힐 수 있다 | 이미지가 안 뜨면 빈 회색 칸으로 둔다 (이모지·글자는 디자인 방향과 맞지 않아 넣지 않는다) |
| 배포 후 DB 연결 실패 | 6주차와 같은 구조 | Vercel 환경변수에 `DATABASE_URL`을 등록한다 |
| 포트 충돌 (`EADDRINUSE`) | 2026-10-12 확인: 3000번은 6주차 가구 쇼핑몰 서버가 사용 중 | 이 프로젝트는 3001번을 쓴다 (`process.env.PORT \|\| 3001`) |
| 범위가 커짐 (컬렉션 등) | MISSION.md의 v1 제외 목록 | 5단계를 통과하기 전에는 손대지 않는다 (상세·수정·삭제·메모는 사용자 결정으로 4.5단계에 넣었다) |
